Why interleaving works

A deep fade is not instantaneous. It lasts while the geometry holds, and every bit sent meanwhile is at risk, so the errors on a radio link arrive in clumps. Interleaving does not remove one single error. It moves them, and that is enough.

What you are looking at

The top panel is the received level over a short window of the walk, in decibels against its own average over that window. It is measured against the local average on purpose: the walker is also getting further away, and that steady loss is path loss, which is a different problem with a different cure. Taking the local average out leaves only the fading.

The dashed line is the level below which the receiver can no longer read a bit. The page uses a hard threshold: a bit is counted wrong when, and only when, the level at that instant is below the line. In reality the probability of an error rises smoothly rather than switching, so this exaggerates the edges of a fade. It gets the thing that matters right, which is that errors come in runs, and it keeps the page exactly reproducible.

The middle panel is the stream cut into blocks, one bar per block, showing how many bits in that block are wrong. The horizontal line is what the error-correcting code can repair. A bar above the line is a block the code cannot save. The bottom panel is the same stream after block interleaving: the blocks are shuffled in groups before transmission and unshuffled on arrival.

Two ways to spread the damage, and they are not the same mechanism

Stallings gives two, and both have a control here.

  • Shuffle your own blocks. The interleaver depth. Your blocks go out in a different order and come back into order at the receiver. The burst still lands where it lands, but it now falls on blocks that end up scattered through your stream, so no single block collects all of it. Your data occupies exactly as much wall-clock time as before.
  • Use time slots that already exist. The number of users sharing the link. On a link divided into time slots, you own one slot per frame, so your blocks go out one frame apart rather than back to back. Your stream is stretched over more wall-clock time, and a fade of fixed duration therefore touches fewer of your blocks. Nothing is shuffled: the damage is spread across the other users instead.

That difference shows in the chips. Raise the interleaver depth and bits in error does not move, because the same bits are hit and only their destination changes. Raise the number of users and bits in error falls, because fewer of the bits inside the fade are yours. The two compose, and that is what Stallings means by combining both giving greater diversity: press First method only, then Both methods at once.

The one thing to notice

The bits in error chip does not change when you move the interleaver depth. Not approximately, exactly. Stallings says this twice, and it is the whole mechanism: the same number of bits is in error, but the error-correcting code is applied to sets of bits that are spread out in time. Interleaving repairs nothing. It converts a few blocks damaged beyond repair into many blocks damaged slightly, and slight damage is what a code is for.

Things worth trying

  • Turn both methods off. Depth 1 and one user. The same fade now destroys a run of consecutive blocks, and the count of lost blocks jumps from zero to four.
  • Share the link with three other people. Press First method only. Nothing is shuffled, yet the loss falls from four blocks to one, because three quarters of the bits inside the fade now belong to somebody else. Their codes deal with their share. This is the method that costs you nothing and is already there whenever a link is shared by time slots.
  • Make the interleaver too shallow. At depth 2 the burst is spread over two blocks instead of one, which is not nearly enough: both still exceed what the code can repair. The depth has to be comparable with the length of the burst measured in blocks, and the burst is long because the geometry holds still for milliseconds.
  • Weaken the code and watch interleaving make things worse. Press A code too weak. When the average error rate across the whole window is already above what the code can repair, spreading the errors evenly means every block is now slightly beyond repair instead of a few being hopeless and the rest perfect. Interleaving buys nothing if the code cannot cope with the average; it only converts bursts into an average.
  • Lengthen the blocks. A 2000-bit block lasts twice as long, so the same fade spans fewer blocks and the code has twice as many repairable bits to play with. Block length, code strength and interleaver depth are three knobs on one tradeoff.
  • Watch the delay. A block cannot be delivered until every block it was shuffled with has arrived, so the depth sets a floor on latency that no processor can remove. Sharing the link multiplies that wait, because the blocks you are waiting for are now a frame apart rather than back to back. That is the cost, and it is why a voice call and a file transfer choose different depths.
