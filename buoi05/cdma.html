Everyone at once, and how one receiver picks out one user

Several senders transmit over the same band at the same instant. Nothing separates them in time and nothing separates them in frequency. The only thing that tells them apart is the code, and this page follows one bit all the way through the receiver.

Each sender takes its bit, multiplies it by its own code, and puts the result on the air. The air just adds. The receiver multiplies what arrives by the code of the one user it wants, adds up the chips, and looks at the sign. Every number below is computed, not drawn.

The three terms, and which one you can get rid of

TermWhere it comes fromWhat you can do about it
The wanted term The code of the user multiplied by itself. Every chip gives +1, so the sum is N and it carries the bit. Nothing needed. It grows with the length of the code.
The other users Every other code measured against the one the receiver is holding. This is the one the code design kills. Choose the codes so that every pair gives zero and the term disappears exactly, however many senders there are. Choose them at random and it does not.
The noise term Thermal noise, with the signs of the code mixed in. Nothing. Multiplying by ±1 leaves noise looking exactly like noise.

What to try

Do thisWatch
Look down the right-hand column with orthogonal codes The row of the user being listened to shows the bit at full size. Every other row shows 0. The receiver is not filtering anything away: the other users simply add up to nothing once their chips are scored against the wrong code.
Leave the codes orthogonal and drag the number of senders from 1 to 7 The middle box stays at exactly 0 the whole way. Seven senders cost the receiver nothing at all.
Switch to codes picked at random, then drag the senders up again The middle box stops being zero and grows. The sum starts to wander, and with enough senders the sign eventually flips and a bit is read wrong.
Set the senders to 1 and turn the noise up Only the third box moves. This is the ordinary noise problem, and the code neither helps nor hurts.
Press new codes a few times with random codes Some sets happen to be better than others. Orthogonal codes are not luck: they are built that way.
