Frequency hopping, and what the code is for

The transmitter changes frequency hundreds of times a second. The receiver has to be on the same frequency at the same instant, or it hears nothing at all. The spreading code is what tells them both where to go next.

Frequency on the vertical axis, time running left to right, exactly like a spectrogram. Each block is one dwell: the transmitter sits on that channel, sends, and jumps. Note what the code is not doing here: it never touches the data. The bits are modulated in the ordinary way, and the code only drives the frequency synthesiser.

What the spreading code is doing

JobWhat happens without it
It tells both ends which channel is next The receiver listens on the wrong frequency and hears nothing. Press wrong code and watch the hit rate collapse to the one-in-N you would get by luck alone.
It makes the order look random A plain ascending sweep would walk into a narrowband jammer at the same predictable moment every cycle, and two systems that started together would collide on every single hop forever.
It separates users Two piconets with different codes only clash when they happen to land on the same channel at the same instant, which is one hop in N.

Where the spreading actually is

At any instant the signal is narrow: Bluetooth occupies one 1 MHz channel, the same width the data needed in the first place. The spreading is in the time average: over a second the transmitter has visited the whole 79 MHz band. That is the opposite of direct sequence, where the signal is genuinely wide at every instant.

It is also where the robustness comes from. A jammer sitting on one channel can only ruin the hops that land on it, which is one in N. Everything else gets through untouched, and an error-correcting code mops up the rest.
